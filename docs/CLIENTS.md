# Устанавливаемый веб-клиент (предварительная версия)

Это PWA существующей панели, а не нативное приложение и не полный релиз
NEXUS. Исходные файлы обслуживаются тем же Python-сервером, отдельного
frontend build step нет. Установка будет доступна только **после развёртывания
этой версии** на HTTPS-сайте и проверки работоспособности сервиса и базы.

- **Веб:** откройте адрес сервиса в современном браузере.
- **Android:** в Chrome откройте сайт и выберите в меню «Установить приложение»
  или «Добавить на главный экран» (название зависит от браузера и версии).
- **Windows и Debian/Linux:** в Chrome или Edge откройте сайт и используйте
  пункт установки приложения в адресной строке или меню браузера. Доступность
  и расположение пункта зависят от браузера и конфигурации устройства.

Запускается тот же серверный интерфейс, с той же авторизацией, правами и CSRF;
ярлык не содержит ключей. Нужны интернет и доступный сервер. При потере сети
уже установленное приложение может показать сообщение об отсутствии связи.
Сервис-воркер не кэширует страницы, API, проекты, сессии или секреты и не
отправляет действия позднее; офлайн-работы с проектами нет. HTML-ответы также
получают `Cache-Control: no-store`. Данные, которые сам браузер сохраняет
(например, cookies и менеджер паролей), управляются его настройками.

Проверка установки требует HTTPS (или localhost для разработки). Для тестирования:

```bash
python -m pytest tests/test_pwa.py -q
node tests/pwa_worker_test.js  # проверка сетевого/offline поведения воркера
node --check orchestration/pwa/register.js
node --check orchestration/pwa/service-worker.js
```

Удаление выполняется средствами браузера/устройства. После удаления можно
очистить данные сайта в настройках браузера. Обновление PWA происходит через
тот же сайт; для активации нового воркера может потребоваться закрыть старые
вкладки приложения.

## Не готово к полному релизу

- Нативные Windows/Tauri и Debian пакеты, Android APK/AAB и Rust CLI не
  собраны и не поставляются. PWA не заменяет проверку на реальных устройствах.
- Существующая схема NEXUS, изоляция legacy API, прямой OpenHands transport,
  конкурентный захват workspaces, LLM Gateway и независимая QA-приёмка требуют
  реализации и аудита; статус `completed` не является доказательством QA.
  Подробнее: [NEXUS-SPEC.md](NEXUS-SPEC.md).
- Само наличие PWA или ответ `/healthz` не подтверждают доступность PostgreSQL,
  OpenHands, GitHub или LLM. Перед production развёртыванием проверьте бэкап и
  историю миграций: при `AUTO_MIGRATE=true` сервер применяет миграции на старте.
  Не восстанавливайте и не меняйте production-базу без отдельного решения.
