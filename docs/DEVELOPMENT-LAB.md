# Лаборатория разработки: текущий инкремент

Это не полный NEXUS и не готовая автономная IDE. Рядом с существующим
Dispatcher добавлены ввод и хранилище исходных материалов и GitHub-интеграция.
Проектные планы по-прежнему не запускают агента. Не считайте `completed`
независимой QA-приёмкой. Другие пробелы — в [NEXUS-SPEC.md](NEXUS-SPEC.md).

## Текст и голос

Текст можно вводить в цель проекта или старую задачу Dispatcher. Кнопка
«Диктовать» добавляет распознанный текст в поле, **не отправляя** его. Это
Web Speech API браузера, не серверная транскрибация: требуется HTTPS/localhost,
разрешение на микрофон и поддерживающий браузер. Распознавание может обращаться
к внешнему сервису браузера и передавать ему аудио; проверьте его политику
конфиденциальности. Если API отсутствует, кнопка отключена. Работа на конкретных
устройствах и языках не гарантируется; язык этого интерфейса — `ru-RU`.

## Файлы проекта

Выберите проект и загрузите один или несколько файлов любого формата, в том
числе архивы. Лимиты: **5 МиБ на файл, 20 МиБ и 100 файлов на проект**.
Загрузка нескольких файлов последовательная, не атомарная: при ошибке уже
загруженные останутся; проверьте список перед повтором. Файл сохраняется как
opaque bytes в PostgreSQL без отдельного шифрования на уровне приложения с размером и SHA-256; имена не являются путями.
ZIP и другие форматы **не распаковываются, не исполняются, не сканируются на
вредоносное ПО**. Скачивание принудительно идёт как attachment с `nosniff`.
Открывайте полученные файлы только в доверенной изолированной среде.

Чтение/запись проверяет membership проекта; удаление — только владелец и с CSRF.
Вложения **не передаются** в OpenHands, не привязаны к целям и планам, не
индексируются и не превращаются в контекст. Не загружайте секреты или данные,
которые не должны попасть в резервные копии БД; администратор базы имеет доступ.
Ограничения покомпонентные, не являются глобальным лимитом диска или хранения.
Файлы исчезают вместе с удалённым проектом. Формального срока хранения нет;
удаление из базы не означает удаления из резервных копий.

API: `GET/POST /api/v1/projects/{project}/files`,
`GET /api/v1/projects/{project}/files/{file}`,
`POST /api/v1/projects/{project}/files/{file}/delete`. Upload — raw body,
обязательный `Content-Length`, заголовок `X-File-Name` с UTF-8 percent-encoding;
запись cookie-сессией требует `X-CSRF-Token`. Ограничения соблюдаются на сервере,
конкурентные загрузки одного проекта сериализуются в БД. Файлы недоступны через
Supabase `anon`/`authenticated`; DB owner/service role остаются доверенными.

## GitHub во вкладке «Интеграции»

Сервер использует существующий `GITHUB_TOKEN`, заданный оператором в окружении;
в UI токен не вводится. Этот доступ **не** подключает GitHub к OpenHands и не
подтверждает права исполнителей. По умолчанию возможен только существующий
просмотр/импорт репозиториев. Опциональную запись включает оператор переменной
`GITHUB_ENABLE_WRITES=true` после оценки рисков и выдачи GitHub-токену только
необходимых прав (для создания и изменения видимости требуется соответствующее
разрешение GitHub на администрирование). Организационные политики могут запрещать
действия. GitHub App/OAuth и управление организациями не реализованы.

Поддерживается создание репозитория **в личном аккаунте токена** как публичного
или приватного и изменение видимости существующего `owner/name`, к которому у
токена есть admin-доступ. Сначала backend получает и показывает имя аккаунта,
репозиторий и желаемую видимость; отдельный диалог требует подтверждения.
Публичный репозиторий может раскрыть всё его содержимое. На сервере намерение
ограничено 120 секундами, привязано к сессии и одноразово; machine bearer или
модель не могут использовать эти endpoints без пользовательской сессии и CSRF.
Это не полноценное доказательство физического присутствия человека и не
неизменяемый audit log. Перезапуск сервера отменяет все ожидающие подтверждения.
Перед сменой видимости повторно проверяются identity, id, разрешения и видимость;
между проверкой и вызовом GitHub сохраняется узкое окно гонки. Сетевой таймаут
может означать, что GitHub уже выполнил действие: **проверьте GitHub перед
повтором**, автоматического retry нет. Созданный репозиторий не добавляется в
allowlist автоматически; импорт выполняется отдельно во вкладке «Система».

API подтверждений: `POST /api/github/prepare` с `{action: "create"|"visibility",
name: "name"|"owner/name", private: true|false}`, затем
`POST /api/github/confirm` с `{confirmation: "..."}`. Оба только для
cookie-сессии + CSRF, независимо от bearer. `GET /api/github/status` показывает
только наличие токена и состояние переключателя, а не действительность токена
или права. Токен не пересылается при HTTP redirects.

## Развёртывание и проверка

Миграция `0011_nexus_files.sql` добавляет таблицу и включённый RLS без client
policies. По умолчанию приложение автоматически применяет миграции при старте:
проверьте целевую базу и резервную копию до deploy; `AUTO_MIGRATE=false`
передаёт миграции оператору. Тесты требуют одноразовой PostgreSQL и удаляют
тестовые таблицы/данные. Тесты fake GitHub не проверяют реальные scopes,
организационные ограничения или доступ OpenHands; нужна отдельная проверка на
разрешённом тестовом аккаунте. Изменения в production этим инкрементом не делались.
