# NEXUS: второй аудит и сверка документации с кодом

Статус: **выполнен для этого checkout**. Основание — чтение всего репозитория
(`orchestration/`, `migrations/`, `tests/`, `docs/`) и запуск полного набора
тестов против реального PostgreSQL (433 теста, 1 пропущен). Это не отчёт о
production: живые OpenHands Cloud, GitHub-аккаунт и Render здесь не проверялись.

Цель документа — убрать расхождения между прежними отчётами и фактическим
кодом, и честно зафиксировать, что реализовано, а что нет.

## 2. Расхождения, найденные при сверке

1. **Прежние отчёты ссылались на работу, которой нет в этом checkout.**
   `docs/NEXUS-SPEC.md` описывает состояние на коммите `7cffe54`, тогда как
   `main` уже содержит проекты и планы (`f372811`). Публичная ветка не содержала
   более поздних отчётов об Evaluation Engine. В этом checkout нет ни
   `orchestration/verification.py`, ни отчётов второго аудита — их необходимо
   получить отдельно, прежде чем считать Evaluation Engine существующим.
2. **README утверждал, что «согласование плана не запускает агентов»** — это
   по-прежнему верно и сохранено: планы не подключены к исполнению. Это
   ограничение, а не временная недоработка, и оно явно описано.
3. **Legacy API не изолирован по проектам** — подтверждено: `/api/workflows`,
   `/api/tasks` остаются owner-level. Проектная изоляция касается только
   `/api/v1/projects/*`.
4. **Секреты в БД.** `0007_cloud_direct.sql` хранит `session_api_key` в
   `conversation_routes` и `cloud_sandboxes`; `0011` хранит `token_hash` (не сам
   токен) для подтверждений. Утверждение «все секреты только в ENV» неверно;
   защита этих таблиц остаётся задачей (RLS включён, грантов нет).

## 3. Что реализовано в этой работе (и что нет)

Реализовано (см. `NEXUS-LABORATORY.md` для API и деталей):

- Файловая лаборатория: загрузка документов, изображений, кода и архивов в
  проект; превью текста и изображений; скачивание; удаление. Байты — в БД.
- Безопасная распаковка: Zip Slip, символьные ссылки, device/FIFO, архивные
  бомбы (по числу записей, размеру и коэффициенту сжатия).
- Рабочие пространства: durable дерево файлов в проекте, редактирование файла с
  unified-diff против исходной версии.
- Голос: запись в браузере и загрузка; серверного распознавания нет, и это
  отражено в данных (`transcript_engine`).
- GitHub: чтение деталей (ветки, коммиты, issues, PR) и **подтверждаемые** записи
  (создание репозитория, смена видимости). Публичность требует отдельного
  подтверждения.
- UI: вкладки «Лаборатория» и «GitHub», диалог подтверждения.

Сознательно **не** реализовано (не выдаётся за готовое):

- **Терминал и запуск тестов/сборок.** Рабочее пространство — это данные, а не
  оболочка: ничего загруженного не исполняется. Изолированный runner —
  отдельная задача с отдельной моделью угроз.
- **Серверное распознавание речи.** Движка нет; транскрипт браузера помечен
  `browser` и не считается серверной проверкой.
- **Streaming-ответы агентов в UI.** Сообщения Sr отправляются, но токен-стрима
  нет.
- **Независимый QA/Evaluation.** Прежнее `completed` остаётся завершением по
  правилам Dispatcher, а не приёмкой.
- **Мультипользовательский IAM.** Есть один сконфигурированный владелец;
  membership создаётся только для него.
- **Исполнение планов.** Согласованный план по-прежнему ничего не запускает.
